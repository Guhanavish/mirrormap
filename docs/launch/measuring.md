# Measure real adoption

The blank [CSV template](../../examples/launch-stats.csv) is a starting point, **not existing analytics**.

Record these metrics weekly when you have actual evidence: week start, public stars/forks/open issues, available GitHub Insights visitors and clones, voluntarily reported successful skill installs, first audits, useful feedback threads and external contributors.

Do not equate stars with installs or clones with unique users. Avoid collecting personal data and private project logs for marketing.

**Suggested first-month learning goals:** three independently reproduced demos, five substantive feedback conversations, two externally submitted issues and one helpful community contribution. These are goals, not promises.

Weekly review:
- What installation route actually worked?
- What stopped the first audit?
- What did users misunderstand about unknown versus missing?
- What single change should be made next?
