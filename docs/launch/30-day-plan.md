# First-month distribution and feedback plan

These are proposed experiments, **not predictions**.

| When | Actions | Evidence of progress |
|---|---|---|
| Days 1–3 | Set GitHub About details/topics; publish an accurate prerelease; test installation on a clean system | Three developers can independently complete setup |
| Days 4–7 | Post a real 30-second demo and a reproducible fixture walkthrough | Three independent reproductions |
| Days 8–14 | Share one technical article; invite five developers to give detailed feedback (not stars) | Useful issues and usability findings |
| Days 15–21 | Publish adapted posts where promotional posts are permitted; respond to questions | Qualified traffic and installation attempts |
| Days 22–30 | Fix the biggest first-audit confusion point; invite an external contribution | A repeat user and an actionable contribution |

Track weekly: GitHub stars/forks/issues (not user counts), Insights visitors/clones when available, reported successful installs, successful first audits, feedback threads and contributors. Metrics should come from observable sources, never fabricated numbers. See [measurement guide](measuring.md).

Experiment ideas: compare a technical case study versus video, test two truthful README CTA labels, and measure time-to-first-result before adding more integrations.
